# 第六轮：人群匹配与商品选择内部复验

[打开本轮图表报告](index.html) · [全部六轮报告](../index.html) · [已验证优化记录](../05_优化记录/优化文档.md)

这次沿用已经研究过的三份公开真人数据，每个条件重新生成三次，完成 **7,200 份正式答卷和 104 份技术试跑**。它检验原有发现是否稳定，不是新增独立真人验证，也没有评测官方 MatrAIx 8B 权重。真实受访者背景始终只发内网 Qwen；DeepSeek Pro 仅收到原生生成的画像和公开题目。

## 先看结果

误差单位为百分点，越低越接近真人。每次先分别评分，再对三次取平均，没有选最好的一次。

| 对照 | 改前 | 改后 | 结论 |
|---|---:|---:|---|
| Qwen：只匹配年龄学历 → 再匹配性别收入 | 15.50 | 15.95 | 没有改善 |
| Pro：只匹配年龄学历 → 再匹配性别收入 | 11.41 | 11.50 | 没有明确改善 |
| 四项人口匹配、同样概率输出：Qwen → Pro | 15.95 | 11.50 | 降低4.46点，95%区间4.04–4.96，三次均改善 |
| 产地二选一：只选一项 → 给各项概率 | 11.30 | 11.54 | 变化不明确；统计方法为2.62 |
| 包装选择：只选一项 → 给各项概率 | 36.14 | 19.53 | 降低16.61点，95%区间13.06–19.42，三次均改善；统计方法为7.32 |

包装的真人拒买比例为32.1%，模型从12.2%提高到23.9%，更接近但仍低估。概率最高项只能识别11.3%的真实拒买选择，不能据此宣称已能找准拒买消费者。产地任务的概率输出降低了对高评分款的过度偏好，却加重了产地和低价选择的偏差；四项平均没有改善。

## 人群与方法

- **Pew Wave 13 合成人群：** 4,317名网络受访者中，4,090人具备四项可对齐背景和全部13题答案，按官方权重建立参照。年龄仅18–64／65+，学历仅本科以下／本科及以上，收入仅低于10万美元／至少10万美元；原二元性别标签按操作规则对应合成标签，不等于两种性别测量完全相同。地区仅固定北美，美国为共同情境。每组240条原生生成画像。基础组与多维组都展示相同四项字段，所有组使用同一分析权重；人格组再加四项生成属性。Qwen和Pro均输出各项概率。
- **产地与包装：** 各沿用原240名评估受访者，与另外708／1,003名统计训练对象按人分开。固定原商品卡、展示顺序、预测提示、真人贴题背景，只改输出单选或概率；全部由Qwen运行。没有把原评估对象改称“新留出样本”。
- **三次生成：** 关闭思考、检索及工具；温度0.7，top_p=1，最多1,536个输出token。每个条件三次独立请求，未声称服务端随机种子可复现。种子20261110固定样本、合成人群匹配和重抽样；原商品任务保留此前种子与拆分。
- **区间：** 2,000次重抽样。合成匹配的真人参照固定；商品按人同步抽真人答案与预测。同画像跨模型／人格比较配对抽样，两套合成人群独立抽样。区间条件于既有三次答卷与训练集，不包含全部模型随机性、统计方法重训和官方复杂调查抽样误差。
- **采用规则：** 单项任务误差至少减少2点、95%区间高于零、三次均改善。多项比较未控制整体错误率。没有将三个任务合成一个不可解释的总分。

## 发现并修正的映射问题

运行中的覆盖核对发现，学历标签写法不一致误排除610条有效背景记录。查看正式分数前即停止运行、修正并重新冻结，完整有效参照从3,517人恢复至4,090人。输入发生变化的285份正式答卷和10份试跑已从有效检查点删除。其余只有请求全文哈希相同时才复用，没有按答案好坏选择。现在未识别的非缺失标签会直接报错。

[映射修正清单](mapping-correction.json)保存旧冻结指纹和处置数量；[纳入排除核对](eligibility-audit.json)保存各类缺失和正式标签计数。早期混用权重的画像增益对照已从统一报告常规选择器撤下，历史原记录与[同权重复算](../09_方法审查/index.html)保留。有效的负面发现不因效果差而删除。

## 文件与复算

| 文件 | 用途 |
|---|---|
| `protocol.json`、`analysis-seal.json` | 冻结方案、输入哈希、运行和评分代码指纹 |
| `synthetic-cohorts.json`、`matching-reference.json` | 纯合成画像、公开题目、真人聚合参照；不含逐人真人记录 |
| `synthetic-responses.jsonl.gz` | 4,392份纯合成答卷，含4,320正式和72试跑；随Git保存 |
| `results.json` | 全部逐题、逐次、配对区间、正确率、拒买与概率误差 |
| `completion-checks.json`、`input-checks.json`、`scoring-checks.json` | 100%完成、请求一致性、输入隔离、商品选项还原和零误差检验 |
| `pilot.log`、`formal.log` | 运行进度，包含映射修正前被中止的阶段；最终有效量以完成核验为准 |
| `experiment-status.json` | 旧比较撤下、保留及无效新答卷删除的依据 |
| `本机运行/freeze.json`、`本机运行/responses.sqlite` | 含真人关联的复算材料，仅本机，不入Git |

6次格式失败尝试（5次概率越界、1次非法单选）按既定规则重试后成功。没有最终缺失答卷。临时服务商凭据已删除，不保存在归档或Git。

从仓库根目录执行；评分使用NumPy，商品统计参照另需SciPy：

```sh
# 不需要本机真人文件，即可从Git归档重新核对全部合成人群成绩
.venv/bin/python examples/sim-to-real/revalidation_archive.py check

# 需要恢复本机运行文件；只重新评分，不调用模型
.venv/bin/python examples/sim-to-real/revalidation_score.py

# 只凭聚合结果离线构建全部报告
.venv/bin/python examples/sim-to-real/retail_report.py

# 字段标签、选项映射、云端边界及验收规则检查
.venv/bin/python -m unittest discover -s examples/sim-to-real -p test_revalidation.py
```

重新准备原始输入需 `pyreadstat==1.3.7`；使用 `uv run --python .venv/bin/python --with pyreadstat==1.3.7 --with httpx --with numpy==2.5.0 python examples/sim-to-real/revalidation.py prepare`。已经冻结的不同输入会触发拒绝覆盖。重新调用模型用同脚本的 `pilot`／`formal`，DeepSeek凭据从进程变量 `DEEPSEEK_API_KEY` 读取，真人商品实验不能改投云端。三次生成并不能保证未来服务端同名模型完全不变。
