# 参数、对照与验收：把文献转为可检验方案

更新：2026-11-10。下列建议尚未运行；不属于已验证优化记录。

## 先分清三种“概率”

1. **生成温度：** 调整模型下一个词元的抽样。它不是顾客选择概率，也不能靠调高就复制心理差异。
2. **模型口头给出的选项概率：** 模型输出“甲60%、乙40%”。需要与真实频率比较，不能因为相加为100%就视为准确。
3. **评分映射的温度：** 将文字映射成五档评分概率时，控制分布摊开程度。它与API的生成温度是两个参数。

购买意愿SSR论文同时涉及第一种与第三种；电动车论文称T=1为calibrated sampling，指按模型softmax分布抽样，并非经过真人数据校准。[SSR附录A.4](https://arxiv.org/html/2510.08338v2) · [电动车§6.1–6.3](https://arxiv.org/html/2403.20252v1)

## 论文实际用过的配置，不等于普遍最优

| 研究 | 提取到的配置 | 它能说明什么 |
| --- | --- | --- |
| 电动车偏好 | Llama 2 7B/13B/70B；LoRA/QLoRA，r=8、alpha=32、dropout=0.1；对比T=0和1并扫描；最多8输出token | 温度有群体与逐人目标的权衡；不能直接搬到长JSON问卷 |
| Centaur | Llama 3.1 70B；QLoRA r=8；1轮；学习率0.00005，batch 32；只计算人类回答部分损失 | 行为训练配方具有参考价值；不是这些单个超参数最优的证据 |
| 消费意愿SSR | gpt-4o、gemini-2.0-flash；top_p=0.9；生成温度0.5或1.5；六组参考句；映射温度1、epsilon=0 | 需要把文本生成与评分映射分开冻结 |
| 41人本地采访 | OpenHermes 2.5 Mistral 7B；追问/改写温度0.7，分类温度0；其余Ollama默认 | 证明一种实现被试用，不证明0.7优于其他温度；默认参数使复现需补环境记录 |

## 第一优先：公开商品评分的输出方式实验

**问题：** 评分比例改善，究竟来自模型判断改变，还是表示和汇总方式改变？

固定同一批人、商品、背景、模型、题序和权重，设置：

- 每题直接交一个分数。
- 直接给所有分数的概率。
- 先给短购买意愿文字，再由固定规则映射为评分概率。
- 对同一批概率只取最大项，作为无需再次生成的诊断。

对文字映射法，再做相同文字、不同固定映射的对照，避免把映射器效果算成“模型更懂顾客”。可以用透明语义参考句或在开发集训练的映射；这两条数据条件不同，分别报告。不要按测试分布选择参考句。这里的短文字不是要求暴露模型内部思维过程。

保留其他真人训练的简单方法；若校准器也使用真人答案，所有使用训练数据的方法采用同样分割。

## 第二优先：信息内容与访谈方式

比较人口背景、结构化购物经历、访谈要点。同一人最好具备三类输入；否则样本差异可能混进信息效果。另设等长度摘要对照，区分字数与内容价值。

访谈采集需记录：真实预算约束、近期同类购物、需求、拒买理由、使用情境及缺失；这是候选采集清单，不是要求假定每项都有效。逐字段效应需分组消融，不能由组合收益反推。

访谈顺序本身也是因素。若能招募新真人，随机安排访谈前后目标测量或独立无访谈对照，预先说明测量的是哪个时点的偏好。别为了获得“更多信息”而直接问出目标商品答案。

## 第三优先：小规模参数筛选

建议候选值：生成温度0、0.3、0.7、1.0；top_p先固定1。**这是我们的候选网格，不是论文结论。** 与原实验保持可比的配置必须保留。不同端点不支持的参数单独记录，不静默改成别的值。

固定模型完整ID、服务构建/量化、提示全文、上下文和输出长度、结构化输出约束、随机种子（如支持）、重试策略。温度0仍应做重复运行以检查服务端不确定性。思考模式或解释要求另设对照，不与温度同时混改。

## 验收要回答四个问题

| 问题 | 指标及解释 |
| --- | --- |
| 总共有多少人会选各项？ | 完整分布误差、极端集中度、拒买份额 |
| 能认准具体顾客吗？ | 逐人概率误差、最高项正确率、拒买与少数选项召回 |
| 商品改一个地方会怎样？ | 属性效应方向和幅度；不能只报相关性 |
| 换商品、时期或人群还成立吗？ | 独立留出结果、分组表现、成本和失败率 |

沿用原项目“改善至少2个百分点、区间高于0”的规则时，只适用于对应的分布误差指标；不可套到Brier分数、KS相似度或相关系数。区间应按真实独立单位重抽，不能把同一个人的多次模型调用当作更多真人样本。

采纳前至少比较：相同输入下的原方案、简单统计参照、优化方案。调参在开发集进行，测试只用冻结方案；报告负面结果，不挑最好的单次生成。
