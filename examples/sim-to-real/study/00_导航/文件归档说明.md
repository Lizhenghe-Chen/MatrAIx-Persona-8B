# 实验文件怎样保存、怎样找回

全部实验的主目录为 `examples/sim-to-real/`，报告和数据档案在其下的 `study/`。打开 [index.html](../index.html) 先读故事和主要对比，再到 [evidence.html](../evidence.html) 核对六轮精确结果及每道题。两页均可离线阅读，完整证据使用仓库内的图表库。[从这里开始](从这里开始.md)按轮次导航，[优化文档](../05_优化记录/优化文档.md)集中记录验证有效和无效的做法。

## 随 Git 保存什么

所有实验代码、冻结方案、公开题目、字段映射、汇总结果、报告、来源、执行日志及文件校验值均随 Git 保存。首轮和模型对比使用的合成画像、纯合成答卷也随 Git 保存。已确认公开许可的小型源数据和问卷一并收录；候选数据只表示已收集，不等于已经完成实验。

本次采用 **单个文件 20 MiB** 的普通 Git 上限，压缩能保留内容的公开表以 `.gz` 保存。MiB 是文件大小单位，约等于平时说的 MB。检查点已有答卷归档时不重复入库；现有路径不做无意义搬动，以免破坏冻结的输入记录、脚本和旧报告链接。

## 统一源数据与本机运行档案

原始数据统一从[共享盘数据源总索引](file:///Volumes/%E5%85%83%E5%AE%87%E5%AE%99%E8%81%94%E5%90%88%E5%88%9B%E6%96%B0%E5%AE%9E%E9%AA%8C%E5%AE%A4/%E5%AE%9E%E9%AA%8C%E6%95%B0%E6%8D%AE/MatrAIx%E5%A4%9A%E5%9C%B0%E5%8C%BA%E9%80%89%E5%93%81%E6%BA%90%E6%95%B0%E6%8D%AE/README.md)读取。共享盘挂载位置不同的电脑可设置 `MATRAIX_DATA_ROOT`，指向包含 README.md 的总目录。 总索引列出历史六轮数据、后续多地区选品数据、其他候选和 Persona 1M，附逐文件校验值。Git 中的小型公开副本与旧本机源包仍是历史归档。

样本索引、逐人预测和检查点仍留在原项目的各轮目录。第五轮和第六轮分别使用各自的 `本机运行/`。跨机器复算应单独恢复这些文件，并遵循源调查原有的数据使用条款。

## 换电脑后能做什么

1. **阅读所有报告、查看全部汇总结果：** 克隆仓库后直接打开 `study/index.html`，无需取得任何被忽略数据。
2. **从汇总结果重建报告：** 在仓库根目录用 Python 3.12 执行 `python examples/sim-to-real/retail_report.py`。只使用标准库及已入库结果，不发模型请求。
3. **逐人重新评分：** 挂载共享盘总库，另恢复本机冻结样本和答卷检查点，再按[各轮复算说明](../README.md)运行。恢复后先核对哈希，不用新下载但版本不同的数据覆盖冻结输入。
4. **重新调用模型：** 还需可用内网 Qwen 和自行配置的服务商凭据。密钥不保存在档案、配置、日志或 Git；真人逐人背景仍只发送内网。

SHA-256 是文件内容的指纹，用来发现文件是否被改动，不代表调查本身没有偏差。已压缩文件同时保留原始内容哈希和压缩文件哈希时，以原始内容哈希判断重新压缩后的数据是否相同。

从仓库根目录核验当前副本：

```sh
python3.12 examples/sim-to-real/archive_inventory.py check
```

缺少本机专用文件会单独计数，不妨碍纯 Git 副本通过；缺少已入库文件或现存文件哈希变化会报错。新增或有意更新资料后，先检查并 `git add` 需要归档的实验文件，再执行 `archive_inventory.py write` 更新清单，最后将清单本身加入 Git。清单不统计自身，避免循环校验。
