# 复算与复用指南

## 先区分三件事

- **查看报告**：直接打开离线 HTML，不需要密钥或网络。
- **重新评分和绘图**：读取本地冻结答卷、校准参数与真人参照，不调用模型，不产生新的调用费用。
- **重新运行实验**：需要数据准入、字段白名单、冻结方案和调用预算；会调用服务。不能把重新调用后的随机回答当成原实验答卷。

以下评分命令都不读取密钥。文件名使用示意路径；正式结果未齐全时，评分器应报错，而不是输出部分数据的“成功”报告。

## 环境

在项目根目录使用 Python 3.12。评分依赖版本记录在 `requirements-score.txt`；原始数据解析的额外依赖在 `requirements-audit.txt`。这两份文件记录当前实际使用版本，不保证所有未来系统均已验证安装。运行器的文件锁依赖 Unix；当前在 macOS 验证。

```sh
python3.12 -m venv .venv-decision
.venv-decision/bin/python -m pip install -r examples/sim-to-real/decision_lab/requirements-score.txt
source .venv-decision/bin/activate
export PYTHONPATH=examples/sim-to-real
```

无需重新创建项目现有环境，也不要在正式运行中升级依赖。

## 从已完成答卷复算

本机材料根目录为 `~/.local/share/matraix-decision-lab/`。每项研究包含 `prepared.json`、`baseline-development.json`、`calibration-v1.json`、`formal-v1/`；合成人群另有 `synthetic-tasks-v1.json` 与 `synthetic-formal-v1/`。这些文件包含私有记录或关联信息，不随公开报告分发。

在下面命令中，`study_directory` 指向某项完整研究目录；`--kind` 为 `dryer` 或 `swiss`，必须与数据对应。输出使用新文件名，避免覆盖既有冻结成绩。

```sh
python -m decision_lab.evaluate_study study_directory --kind dryer --calibration study_directory/calibration-v1.json --output individual-analysis.json
python -m decision_lab report --input individual-analysis.json --output individual-report.html
python -m decision_lab.evaluate_population study_directory --kind dryer --output population-analysis.json
python -m decision_lab report --input population-analysis.json --output population-report.html
```

个体评分会重新核对开发阶段的选参结果，再核对各正式组的请求、回答版本和相同测试样本。合成人群评分另核对冻结设计、分组和实际商品组合，不创建虚拟人与真人的逐人答案配对。报告命令根据结果类型选择对应版式。

区间使用固定种子和 2,000 次按人重抽样。开发与测试不可交换；输出摘要不能替代原始检查点来复算。主评分目前要求全部任务完成，严于方案的 98% 最低门槛；若确实无法恢复少量任务，需要先明确共同样本及缺失处理，不能直接静默丢弃。

## 六类入口如何对应

| 工作 | 入口 | 注意 |
|---|---|---|
| 检查标准化真人数据 | `python -m decision_lab check --input prepared-study.json` | 结构检查不代替作者题面、许可与时点审查 |
| 冻结通用真人方案 | `python -m decision_lab freeze --input prepared-study.json --config frozen-config.json --output seal.json` | 要求五项入场审查通过；已有冻结文件不覆盖 |
| 调用模型 | `python -m decision_lab run` | 需显式输入、配置、冻结清单、阶段及检查点；本轮使用研究专属运行入口 |
| 评分 | 上面的 `evaluate_study` / `evaluate_population` | 从完整检查点复算；通用 `score` 适用于标准化概率输入 |
| 生成报告 | `python -m decision_lab report` | 不调用模型，不重新选参 |
| 核验归档 | `python -m decision_lab verify --input archive.json` | 校验归档相对路径与 SHA-256；项目全量归档另用 `archive_inventory.py check` |

## 复用到其他项目时

通用的输入白名单、调用、概率校验、检查点、分割和评分逻辑位于 `core.py`、`provider.py`、`runner.py`、`checkpoint.py`、`scoring.py` 等模块。商品属性解析和背景编码在各研究适配器中；换数据时应替换适配器并重新审查，不能照抄烘干机的属性列或学历映射。

模型名称和服务参数来自配置。新端点必须单独验证身份与输出协议；本轮只有 DeepSeek Pro 经过正式配置冻结，框架可配置不等于其他模型已被验证。

MatrAIx 合成人格生成是单独的数据准备步骤。一般问卷或真人背景预测不需要加载它的完整图模型，也不需要 Persona 1M 大文件。
