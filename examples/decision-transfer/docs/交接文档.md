## 现在的结论与不做的事

- 结论：加入真实测量资料能降低误差，但**帮助不来自「对应到本人」**；混淆资料反而更好。按冻结门槛判为未通过。
- 不做：服装/食品品类外推、扩样、换指标。任何改法都要另立版本（见结果记录末节）。
- 已做：48 人四臂、216 次 Pro 调用、配对 2000 次重抽样、事后诊断（模型确实随资料变动但很少改判，自信却答错更多）。

## 怎么跑

```sh
# 复算准入（只读源数据，写 data/admission）
.venv/bin/python examples/decision-transfer/src/admission.py

# 冻结（文件已存在时会拒绝覆盖，符合设计）
.venv/bin/python examples/decision-transfer/src/freeze_inputs.py --dry-run

# 正式调用（会先查上限与已成功记录）
.venv/bin/python examples/decision-transfer/src/run.py --model pro --set formal

# 出分（只读本机台账与答案）
.venv/bin/python examples/decision-transfer/src/score.py --model pro --which formal

# 验收
.venv/bin/python -m unittest discover -s examples/decision-transfer/tests
.venv/bin/python examples/decision-transfer/src/check_protocol.py
.venv/bin/python examples/decision-transfer/src/verify.py
```

## 设计上必须守住的点

- 四臂同人、同题、同顺序、同参数；唯一差别是允许的资料。v2 只加了一句四臂共用的预测指令。
- 事实只在「本人」和「错配」两臂出现，字段、格式、缺失规则逐字一致；错配必换人且只用一次。
- 模型输入里没有人员编号、权重、真实选择或任何由选择算出的分数。`verify.py` 每次都复查这一点。
- 重复请求是故意发的（测输出波动），因此它与正式请求共用正文但使用独立键；正式成功请求永远不会被重发。
- Qwen 只做技术检查，不参与任何效果结论；正式成绩只来自 Pro。

## 已知限制（写报告时必须带上）

- 无法复现作者的答题过快/登记不符剔除，样本框架是「选择有效＋29 项齐全」。
- 只有一个研究通过准入，因此本阶段任何结果都只是**单一研究内的探索性筛查**，不能称跨研究复现。
- 错配供体按同研究、同品类、同粗年龄学历（优先同性别）匹配，区间只条件于这一批供体，不代表所有可能错配。
- 彩色 A–E 影响标度的字母对应无法恢复，输入只用等级文字。
